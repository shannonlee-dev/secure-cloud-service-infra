# 클라우드 실습 재현 안내

## 준비

자신의 AWS 실습 계정과 EC2·VPC 관리 권한, 관리자 공인 IP, 키페어, SSH 클라이언트를 준비합니다. HTTPS를 재현할 때는 자신이 관리하는 DNS 이름이 필요합니다. 기존 배포 기록의 IP·도메인·리소스 ID는 과거 값이며 새 환경에 재사용하지 않습니다.

## 구성 순서

1. 실습용 VPC와 공개 서브넷을 준비합니다.
2. 인터넷 게이트웨이를 연결하고 라우팅 테이블에 `0.0.0.0/0` 경로를 추가합니다.
3. 보안 그룹에서 HTTP 80과 HTTPS 443을 서비스 목적에 맞게 열고 SSH 22는 현재 관리자 IP의 `/32`로 제한합니다.
4. Ubuntu EC2에 공개 IP를 할당하고 자신의 키페어로 접속합니다.
5. nginx를 실행하고 호스트 내부 HTTP 응답을 확인합니다.
6. 자신의 도메인을 새 공개 IP로 연결하고 인증서를 설정합니다.
7. Docker 실행 실습을 별도 단계로 확인합니다. 호스트 nginx와 컨테이너가 같은 포트를 동시에 점유하지 않도록 실행 구성을 확인합니다.

이 저장소에는 자동 설치·배포 코드가 없습니다. 아래 검증을 기록할 때 서버 버전·실행 방식·포트·인증서 구성을 함께 남깁니다. 직접 설치와 컨테이너 단계의 결과를 섞어 현재 운영 구성으로 설명하지 않습니다.

## 검증 순서

라우팅 → 보안 그룹 → 공개 IP·DNS → 서버 프로세스 → HTTP·HTTPS 순서로 확인합니다. 호스트 내부 확인 예시는 다음과 같습니다.

```bash
sudo systemctl status nginx --no-pager
sudo nginx -t
curl -I http://127.0.0.1
sudo docker ps
```

DNS와 외부 접속 검증에는 자신의 도메인을 사용합니다. IAM 오류는 실패한 작업을 확인한 뒤 필요한 권한만 추가하는 원칙으로 다룹니다. [오류 분석](troubleshooting.md)과 [기존 배포 기록](deployment-record.md)을 함께 참고합니다.

## 정리와 증빙

실습 종료 후 [정리 체크리스트](cleanup-checklist.md) 순서로 자신의 실습 리소스를 확인합니다. EC2·볼륨·공개 IP 등 과금 대상과 연결된 네트워크 자원을 구분하고 삭제 결과를 기록합니다. 현재 리소스 삭제는 이 문서 검사나 CI에서 수행하지 않습니다.
